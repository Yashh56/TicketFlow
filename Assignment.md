# **Full Stack Developer – Technical Assignment** 

## **Project: Support Ticket Management System** 

**Experience Level:** 0–1 Years **Submission Timeline:** 27/11/2026 

### **1. Objective** 

Develop a Mini Helpdesk System that allows users to raise support tickets and administrators to manage and resolve them. 

The objective is to evaluate your understanding of backend development, API design, database management, authentication, authorization, and application architecture. 

### **2. Technology Stack** 

#### **Backend (Required)** 

- Node.js 

- Express.js 

- JavaScript or TypeScript 

#### **Database** 

- MongoDB or PostgreSQL 

#### **Frontend** 

- React.js or Next.js 

You are free to choose your preferred libraries and tools, provided the core requirements are fulfilled. 

### **3. Functional Requirements** 

#### **A. User Authentication** 

- Users should be able to register and log in. 

- Implement secure authentication using JWT. 

- Support two user roles: User and Admin. 

- Restrict access to features based on user roles. 

#### **B. Ticket Management** 

Users should be able to: 

- Create support tickets. 

- View their submitted tickets. 

- Edit and delete their tickets where appropriate. 

- Track ticket status. 

- Add comments to their tickets. 

Each ticket should have relevant information such as title, description, category, priority, status, etc. 

#### **C. Admin Management** 

Administrators should be able to: 

- View all submitted tickets. 

- Filter tickets based on status and priority. 

- Update ticket status and priority. 

- View ticket details and associated comments. 

- Manage tickets submitted by different users. 

#### **D. Comments** 

- Users should be able to add comments to their tickets. 

- Administrators should be able to respond to any ticket. 

- Comments should be associated with the respective ticket and user. 

### **4. Event Handling & Action Management** 

Implement a basic event-driven workflow for important actions performed within the application. 

The system should identify and handle events generated by user and admin activities. 

Examples of events and actions include: 

- **Ticket Created:** Trigger an event when a new support ticket is submitted. 

- **Ticket Updated:** Trigger an event when ticket details are modified. 

- **Status Changed:** Trigger an event when an administrator changes the ticket status. 

- **Comment Added:** Trigger an event when a user or administrator adds a comment. 

- **Ticket Resolved:** Trigger an event when a ticket is marked as resolved. 

Based on these events, the system should perform appropriate actions, such as maintaining an activity log or generating notifications. 

Candidates are free to decide how events are handled and how actions are executed within their application. 

### **5. Technical Expectations** 

Your application should demonstrate: 

- Well-structured and maintainable backend code. 

- Proper REST API design. 

- Secure authentication and authorization. 

- Appropriate database design. 

- Input validation and error handling. 

- Proper access control and data protection. 

- Clean separation of application responsibilities. 

### **6. Bonus Features (Optional)** 

You may implement additional features to improve your application: 

- Search and pagination. 

- Sorting and filtering. 

- Dashboard with ticket statistics. 

- Email notifications. 

- API testing and automated tests. 

- Frontend interface using React or Next.js. 

- Docker support.

Please submit:

3. API documentation or Postman collection. 

4. Database design explanation. 5. Live deployment link. 

### **8. Evaluation Criteria** 

Submissions will be evaluated based on: 

- Problem-solving and implementation approach. 

- Backend architecture and code quality. 

- API design. 

- Database design and management. 

- Authentication and authorization. 

- Security and error handling. 

- Documentation and testing. 

Candidates should be prepared to explain their implementation, database design, architectural decisions, and challenges faced during the technical interview.
